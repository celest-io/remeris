**remeris** is a release tool written in Go. It reads Knope's `knope.toml`, `.changeset/` files and Git tag formats, writes the same file edits and changelog output, and prints the same messages. If your project releases with [Knope](https://github.com/knope-dev/knope), you can switch the binary and keep everything else.

:::note
Status: the first phase is a drop-in replacement for [Knope](https://github.com/knope-dev/knope) 0.23.1. Every step that Knope's `knope.toml` can use is implemented. The [differences](/docs/differences) are listed on their own page.
:::

## Install

<Tabs>
  <Tab title="mise">
    With [mise](https://mise.jdx.dev) and its [packslip](https://packslip.dev) backend, which checks the signed release bundle (`packslip.sigstore.json`) before it unpacks anything:

    ```sh
    mise use -g packslip:github.com/celest-io/remeris
    ```

    The signer fingerprint of remeris is `ps1_p2ti4zisstvj4fgdichvcpnhhq` (it comes from the repository ID of `celest-io/remeris`, so it survives a rename). Releases from v0.0.2 on carry the bundle. See [Releasing](/docs/releasing#install-with-mise-and-verify-with-packslip) for the other ways to verify a download.
  </Tab>
  <Tab title="Go">
    ```sh
    go install github.com/celest-io/remeris/cmd/remeris@latest
    ```
  </Tab>
  <Tab title="From source">
    From a checkout, with [mise](https://mise.jdx.dev) (the build task injects the version information):

    ```sh
    mise install
    mise run build   # writes build/remeris
    ```
  </Tab>
</Tabs>

## Quick start

In a Git repository with a package file such as `Cargo.toml`, `package.json` or `pyproject.toml`, and no `knope.toml`:

<Steps>
  <Step title="Generate a configuration">
    ```sh
    remeris --generate
    ```

    Writes a `knope.toml` with the release, document-change and get-version workflows. A repository without a `knope.toml` already has these three workflows with the same defaults, so `--generate` only saves them to a file you can edit.
  </Step>
  <Step title="Record a change">
    ```sh
    remeris document-change
    ```

    Records a change file for the next release.
  </Step>
  <Step title="Preview the release">
    ```sh
    remeris release --dry-run
    ```

    Shows what a release would do, and changes nothing.
  </Step>
  <Step title="Release">
    ```sh
    remeris release
    ```

    Prepares and creates the release.
  </Step>
</Steps>
